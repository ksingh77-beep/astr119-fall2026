❯ i'm confused about p_next. are they the values which we are supposed to get   
  after running the code?                                                       

⏺ Not quite. p_next is a temporary value computed during each pass of the loop,
  not the final answer.

  Think of climbing stairs. To reach Pₙ you have to step through P₂, P₃, … one
  at a time, and each step only needs the two values just below it:

  - p_prev: the value one step back
  - p_curr: the value at the current step
  - p_next: the value one step up, computed from those two

  After computing p_next, you move up one step: p_prev takes the old p_curr, and
  p_curr takes p_next. Then the loop repeats.

  Here's what the variables hold for legpoly(3, 0.5):

  ┌─────────────┬─────┬────────┬──────────┬────────┐
  │             │  k  │ p_prev │  p_curr  │ p_next │
  ├─────────────┼─────┼────────┼──────────┼────────┤
  │ before loop │ –   │ P₀ = 1 │ P₁ = 0.5 │ –      │
  ├─────────────┼─────┼────────┼──────────┼────────┤
  │ pass 1      │ 1   │ P₀     │ P₁       │ P₂     │
  ├─────────────┼─────┼────────┼──────────┼────────┤
  │ after shift │     │ P₁     │ P₂       │        │
  ├─────────────┼─────┼────────┼──────────┼────────┤

  ├─────────────┼─────┼────────┼──────────┼────────┤

  └─────────────┴─────┴────────┴──────────┴────────┘

  The loop ends there, and p_curr holds P₃, which is the answer returned as y.
  So p_next takes on every intermediate value along the way. Only the last one

  for P₂ only. Every degree has its own closed-form polynomial:

  - P₂ = ½(3x² − 1)
  - P₃ = ½(5x³ − 3x)
  - P₄ = ⅛(35x⁴ − 30x² + 3)
  - …and so on, with different coefficients each time

  Your loop has to work for any n, and the test asks for P₃₅₀₁. You can't write
  3,501 separate formulas into the code, and the coefficients for high degrees
  become huge numbers that are hard to compute accurately.

  The recursion (k+1)P_{k+1} = (2k+1)x P_k − k P_{k-1} is one rule that works at
  every step. The only things that change from pass to pass are k and the two
  previous values. That's why the docstring says it's "the only efficient way to
  calculate values of Legendre polynomials of high degree."

  Your current line also has a more immediate problem. Since 0.5*(3*x**2-1)
  doesn't involve k, p_prev or p_curr, it gives the same number on every pass.
